# 002. ESP32-S3: мигание при работе микрофона

**Статус:** решено в проверенной конфигурации.  
**Решение проверено:** 2026-11-01.

## Симптомы

После перехода на Arduino-ESP32 **3.3.12** (`espressif32@8.0.0`) с FastLED **3.10.3** на S3-лампе появились короткие вспышки при включённом аудиорежиме. Они наблюдались и под музыку, и в тишине, в эквалайзере и эффектах с `Audio Mode = Effect`. Без аудиозахвата изображение было стабильным.

## Проверенное решение

В текущей конфигурации с Arduino-ESP32 **3.3.12** / ESP-IDF **5.5.5** и FastLED **3.10.8** пользователь подтвердил нормальную аудиореакцию без миганий. Аудиоалгоритмы, пороги и сглаживание для этого не менялись.

См. также [проблему 001](001-esp32-s3-fastled-white-matrix.md): прежний запрет обновлять FastLED на S3 не относится ко всем сочетаниям core и библиотеки.

## Диагностика и обход для FastLED 3.10.3

- С постоянным `AudioFrame` мигание сохранялось. Когда вызов `Microphone::tick()` пропускался при том же входе эффекта, мигание исчезало. Это показало зависимость от выполнения аудиотракта, но не установило точный механизм сбоя.
- На FastLED 3.10.3 использовался асинхронный RMT5 без DMA; чтение ADC выполнялось через oneshot-драйвер с критическими секциями. Конфликт обслуживания прерываний рассматривался как гипотеза, а не измеренная причина.
- Увеличение буфера RMT с **48 до 96 символов** уменьшило частоту мигания примерно вдвое по визуальной оценке. При **192 символах** мигание исчезло, настоящая аудиореакция работала.

Для этого обхода в [extra_script.py](../../extra_script.py) был добавлен общий build define `LED_STRIP_RMT_DEFAULT_MEM_BLOCK_SYMBOLS_MULTIPLIER=4`. В FastLED 3.10.3 он задаёт 192 символа и должен применяться к C-коду библиотеки, а не только к скетчу. На S3 настройка занимает четыре блока памяти RMT TX, оставляя возможность **одного RMT-выхода**. Для лампы с одним LED-контроллером этого достаточно; в проектах с несколькими выходами ресурсы нужно проверять отдельно.

Этот define пока сохранён в проекте, но в FastLED 3.10.8 реализация RMT5 и управление памятью переработаны. Нельзя считать старый define действующей настройкой буфера новой версии без отдельной проверки.

Временные диагностические логи и подмены `AudioFrame` после расследования удалены. Точный механизм сбоя не измерен.
