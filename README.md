# GyverLamp

Здесь в проекте только прошивка и симулятор, схемы, инструкция по сборке в оригинальных репозиториях.

Цель проекта:

- разобраться в прошивках для микроконтроллеров и C++
- структурировать файлы проекта, отвязаться от скетчей Arduino
- сделать так, чтобы можно было легко добавлять новый функционал

Ссылки на аналогичный проекты, идеями которых вдохновлен, также по этим же ссылкам схемы сборки лампы:

- [GyverLamp2](https://github.com/AlexGyver/GyverLamp2) от AlexGyver
- [GyverLamp](https://github.com/Whilser/GyverLamp) от Whilser
- [GyverLamp](https://github.com/gunner47/GyverLamp) от gunner47
- [FieryLedLamp](https://github.com/MishanyaTS/FieryLedLamp) от MishanyaTS

## Особенности

### Железо

- Контроллер ESP32-S3, ESP32, ESP8266
- Гибкая адресная матрица 16×16 WS2812B RGB
- Сенсорная кнопка на TTP223
- Микрофон MAX9814, без конденсатора между OUT и A0

#### Поддерживаемые контроллеры

- **ESP32-S3** — рекомендуемая плата;
- **ESP32** (не проверено). Проект поддерживает классический ESP32 через target `esp32dev`;
- **ESP8266** — поддерживается и подходит для базовой лампы на NodeMCU или Wemos D1 mini. При включении нескольких ресурсоёмких функций, например MQTT и микрофона, возможны нестабильная работа, лаги эффектов и проблемы с WiFi. Для таких конфигураций рекомендуется ESP32/ESP32-S3.

##### ESP32-S3

- Проверенная плата: **Tenstar Robot ESP32-S3-Zero**, ESP32-S3FH4R2, 4 МБ flash и 2 МБ PSRAM. Используется конфигурация, совместимая с Waveshare ESP32-S3-Zero; это не утверждение идентичности производителя.
- Внешнее подключение: WS2812 — GPIO1, кнопка TTP223 (в покое LOW, при касании HIGH) — GPIO3, аналоговый микрофон — GPIO5 (`ADC1`). GPIO21 занят встроенным RGB; не используйте GPIO0, GPIO19/GPIO20 (native USB) или GPIO21 для внешней периферии.
- Для native USB: подключите плату по USB; при необходимости удерживайте `BOOT`, кратко нажмите `RESET`, отпустите `RESET`, затем `BOOT`.

##### ESP32

- Типовая плата: **ESP32-WROOM-32E** с профилем `esp32dev`.
- Внешнее подключение: WS2812 — GPIO18, кнопка TTP223 (в покое LOW, при касании HIGH) — GPIO27, аналоговый микрофон — GPIO34 (`ADC1`).
- Для USB-прошивки подключите плату через USB-UART. Обычно auto-reset срабатывает сам; если порт не переходит в загрузчик, удерживайте `BOOT`, кратко нажмите `EN`/`RESET`, затем отпустите `BOOT`.

##### ESP8266

- Типовая плата: **NodeMCU** или **Wemos D1 mini**.
- Внешнее подключение: WS2812 — GPIO2 (`D4`), кнопка TTP223 (в покое LOW, при касании HIGH) — GPIO4 (`D2`), аналоговый микрофон — `A0`.
- Для USB-прошивки подключите плату через USB. Обычно auto-reset срабатывает сам; если прошивка не начинается, удерживайте `FLASH`/`BOOT` (GPIO0), кратко нажмите `RESET`, затем отпустите кнопку.

### Прошивка

- PlatformIO + Arduino
- Больше 20 отобранных эффектов, настройка яркости и параметров каждого эффекта, плавное переключение
- Палитра, большенство эффектов работает с ней
- Режим ротации эффектов: последовательно или случайно
- Поддержка микрофона для модуляции яркости и других параметров эффектов, специальный эффект Equalizer
- Упор на MQTT + Home Assistant
- Web UI
- Поддержка некоторых мобильных приложений, управление по UDP протоколу
- Таймер автоотключения
- Уведомления: системные (WiFi, MQTT, OTA) и пользовательские, возможность заглушить их в ночное время
- Все работает на последних версиях библиотек, но на всякий случай версии зафиксированы
- Основные зависимости:

  - `fastled/FastLED` - работа со светодиодной матрицей
  - `GyverLibs/Settings` - web ui
  - `paulino/HaMqttEntities` - MQTT + Home Assisntant
  - `gyverlibs/uButton` - работа с сенсорной кнопкой

### Симулятор

- Браузерный WASM-симулятор эффектов: смотреть и настраивать в браузере без лампы, прошивки и ESP8266.
- Выбор эффекта и палитры, яркость/скорость/масштаб/FPS, пауза и покадровый шаг, diffuser-превью под белый плафон.
- Детерминированный Node-экспортёр исполняет тот же WASM: `just sim catalog` выводит каталог, `just sim render <args>` экспортирует эффект. Результаты лежат в игнорируемом `.artifacts/`; отсутствующие или устаревшие WASM identity/artifacts отклоняются до экспорта.
- Локальные request-файлы для детерминированного рендера создавайте в игнорируемом `.artifacts/requests/`. Результаты рендера сохраняйте в `.artifacts/sim/` или другом подкаталоге `.artifacts/`; общие переиспользуемые fixtures хранятся в отслеживаемом `sim/fixtures/requests/`.

  ```bash
  just sim render --request .artifacts/requests/<name>.json --out .artifacts/sim
  ```

- Полные команды, request и schema экспортёра: [`sim/README.md`](sim/README.md).
- Онлайн: <https://ilyasshafigin.github.io/gyverlamp/>
- Локальный запуск описан в разделе «Разработка».

### WiFi

- Если сохранённых настроек WiFi нет, лампа запускает точку доступа для настройки: `GyverLamp` / `12345678`, адрес `192.168.4.1`.
- Если настройки есть, лампа запускает неблокирующую 60-секундную кампанию подключения к домашнему WiFi и повторяет неудачные попытки каждые 5 секунд.
- Если за кампанию STA не подключилась, лампа один раз открывает точку доступа для настройки и продолжает попытки подключения. Точка доступа не открывается повторно в этой кампании.
- После успешного подключения точка доступа выключается, IP-адрес лампы выводится в Serial и может быть показан на матрице 5 нажатиями кнопки.
- Резервная точка доступа выключается после 5 непрерывных минут без клиентов. Точка доступа при пустых сохранённых настройках остаётся доступной постоянно.
- Web UI доступен для настройки через точку доступа; PlatformIO OTA требует подключения STA к домашней сети.

### Кнопка

- TTP223 подключайте с общей землёй и логическим уровнем 3.3 В.
- 1 нажатие — включить/выключить лампу; если активно пользовательское уведомление — выключить его.
- 2 нажатия — следующий эффект.
- 3 нажатия — предыдущий эффект.
- 5 нажатий — показать IP-адрес лампы на матрице.
- Удержание — плавно менять яркость текущего эффекта; каждое новое удержание меняет направление регулировки.

### Уведомления

- Системные уведомления показываются поверх эффекта и слегка затемняют фон.
- WiFi: подключение — мягкий синий пульс, успешное подключение — короткий зелёный пульс, ошибка — оранжевый пульс около 10 секунд.
- MQTT: подключение — фиолетовый пульс, успешное подключение — короткий бирюзовый пульс, ошибка — янтарный пульс около 10 секунд.
- PlatformIO OTA в сборке с `USE_OTA`: во время прошивки — бирюзовый прогресс/бегущий огонёк сверху, успех — зелёный пульс, ошибка — красный двойной пульс. Обновление HTTP `/ota` от SettingsAsync работает независимо.
- Пользовательские уведомления включаются через Home Assistant/MQTT: выбрать `Уведомление` (`Warning` или `Alarm`) и при необходимости задать `Длительность уведомления` в секундах.
- `Warning` — оранжевый пульс всей лампы, `Alarm` — быстрый красный пульс всей лампы. `Off` выключает пользовательское уведомление.
- Можно заглушить уведомления в заданный интервал, когда питание выключено. Тревога, предупреждения и OTA-статусы продолжают показываться.

### MQTT / Home Assistant

- MQTT работает только при подключённой STA. Потеря WiFi прерывает транспорт; после возврата STA сервис подключается снова.
- В Web UI раздел MQTT показывает cached status. `Enabled` и `Restart MQTT` меняют runtime-политику; она отдельно в EEPROM не сохраняется.
- `Save and apply` сначала сохраняет host/port/user/password в EEPROM. Только успешный commit применяет новые credentials в runtime.
- После ошибки брокера сервис повторяет попытки с backoff 5, 10, 20, 40, затем 60 секунд; ошибка не выключает MQTT навсегда.
- После reconnect Home Assistant получает discovery и полный snapshot состояния. Обычные изменения публикуются только для dirty entity; полный пересчёт targets выполняется также раз в 30 секунд, telemetry обновляется раз в минуту.

## Разработка

### Как запустить проект локально

1. Склонировать репозиторий:

    ```bash
    git clone <url-репозитория>
    cd gyverlamp
    ```

2. Установить PlatformIO, если он ещё не установлен. Например, через VS Code расширение PlatformIO IDE или через CLI:

    ```bash
    pip install platformio
    ```

    Для коротких команд можно также установить [`just`](https://github.com/casey/just).

3. Создать локальный конфиг из примера:

    ```bash
    cp platformio.local.example.ini platformio.local.ini
    ```

4. Отредактировать `platformio.local.ini` под свою лампу:

   - `AP_SSID` — имя WiFi-точки лампы в режиме настройки;
   - `CURRENT_LIMIT` — лимит тока блока питания в миллиамперах; перед выводом кадра прошивка рассчитывает безопасную яркость для текущего содержимого матрицы и пропорционально ограничивает запрос, а FastLED сохраняет дополнительный аварийный лимит;
   - `upload_port` — IP-адрес лампы для OTA-прошивки, только после первой настройки WiFi, если IP ещё неизвестен;
   - при необходимости добавить свои env'ы для нескольких ламп.

    `platformio.local.ini` не попадает в git, поэтому в нём можно держать локальные IP-адреса и настройки конкретного железа.

    Публичный `platformio.ini` содержит только общие настройки проекта. Все настройки конкретной лампы находятся в `platformio.local.ini`.

5. Собрать прошивку:

    ```bash
    just lamp build lamp1_usb
    ```

    Для проверки собирайте ровно один целевой env; например, `just lamp build lamp1_ota`.

6. Первая прошивка обычно делается по USB:

    ```bash
    just lamp upload lamp1_usb
    ```

    После этого лампа поднимет точку доступа, где можно настроить WiFi и MQTT.

7. Настроить WiFi и включить PlatformIO OTA

    При первом запуске лампа создает точку доступа, по умолчанию это `GyverLamp`, пароль `12345678`.
    Нужно подключиться к ней, открыть адрес "192.168.4.1" и ввести название и пароль локального WiFi, сохранить и перезагрузить.

    После перезагрузки лампа подключится к WiFi, роутер выдаст ей IP, по этому IP можно будет продолжить настройку. Рекомендуется зафиксировать этот IP за ней.
    Дальше можно настроить MQTT для её управления из Home Assistant. Открыть новый IP-адрес лампы в браузере, и ввести данные в разделе MQTT.

    В сборке с `USE_OTA` открыть раздел `OTA` в Web UI, включить `Enabled` и дождаться STA-подключения. Env с `upload_protocol = espota` задаёт upload, но сам не включает listener в работающей лампе.

8. Последующие прошивки можно делать через PlatformIO OTA, если listener включён, STA подключена и в `platformio.local.ini` указан правильный `upload_port`:

    ```bash
    just lamp upload lamp1_ota
    ```

### Runtime smoke checklist

После явной прошивки устройства:

1. Подключить лампу к STA и открыть Web UI.
2. В MQTT сохранить корректные credentials через `Save and apply`; проверить статус `Online`.
3. В Home Assistant проверить discovery, команду и обновление фактического состояния.
4. Отключить WiFi или брокер: MQTT должен перейти в ожидание/retry без перезагрузки; вернуть связь и дождаться `Online`.
5. Проверить `Enabled` и `Restart MQTT`: они применяются runtime, без отдельного сохранения политики в EEPROM.

### Локальный симулятор эффектов

Симулятор живёт в `sim/` (подробнее: [`sim/README.md`](sim/README.md)). Запуск локально:

```bash
just sim run
```

`just sim run` сначала собирает WASM-артефакты, потом поднимает статический сервер на <http://localhost:8080>.

Остальные команды: `just sim build`, `just sim test`, `just sim catalog`, `just sim render <args>`.

### LSP / `compile_commands.json` (для агентов)

LSP (clangd) использует `compile_commands.json` в корне проекта.  
Он не лежит в репозитории и пересоздаётся вручную.

Сгенерировать для default env (`lamp1_ota`):

```bash
pio run -e lamp1_ota -t compiledb
```

Если LSP не видит Arduino/ESP8266 или библиотечные хидеры — настройки `extra_script.py` уже включают toolchain-инклуды (`COMPILATIONDB_INCLUDE_TOOLCHAIN=True`).
